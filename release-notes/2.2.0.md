# VxFiles 2.2.0

## Automation Tools

The Info Pane gains a third tab, **Tools**, listing the Automation Packages installed on this machine and the actions inside them. Actions run against the folder and selection you have open, report progress while they work, and can be cancelled.

Everything needed to run an action ships inside the installer. There is no Python to install and nothing is downloaded on first use.

### Running an action

- Pick a file or folder, open **Tools**, and press **Run** on an action that accepts it. A disabled Run button says why in its tooltip: nothing selected, wrong file type, no folder open, or something already running.
- The first run of a package asks you to trust it, and shows what you are agreeing to: where the package is installed, every action it contains — not only the one you pressed — how many items are selected, and any external program it will launch. Trust is remembered until the package or the runtime changes.
- An action can ask VxFiles to refresh the folder or select the files it produced. Those requests are honoured only while you are still in the folder the action ran in; navigate away and they are reported as skipped rather than applied somewhere unexpected.
- Closing the window stops any action still running, along with anything it started.

### Installing a package

Use **Open packages folder** in the Tools tab and copy a package folder in. It appears without restarting. A package that fails validation is listed as disabled with the reason attached, so a broken package is visible rather than silently absent.

## Fixes

- Two packages sharing an id no longer break the Tools tree. Both are shown and disabled so the collision can be found and repaired.
- Running an action no longer leaves Python bytecode inside the package folder. That change had been invalidating the package's own trust, so an unchanged package could ask for consent a second time.
- A completed run now reports the summary the action itself wrote, instead of only its state.

## Notes for this release

Package trust covers the automation runtime as well as the package. Because this release ships that runtime for the first time alongside a changed runner, every package you trust here is trusted against this version; a future release that changes the runtime will ask again.
